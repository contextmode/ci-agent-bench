# Review of PR #65841: Preserve input through ACP reconnect and replay

## Overall
The design is careful. Recovery is captured as plain data when the view moves to `LoadError`. Retry never auto-resends. Peers that can't do full replay get an error instead of a history-less resume. The tests are thorough. They cover failure, auth gating, repeated retry, opaque content, and the discard path. The `AcpThreadEvent::ConnectionLost` variant is added consistently in every exhaustive match (`agent_diff.rs`, `conversation_view.rs` ×2, `acp_thread.rs`).

## Potential bugs and concerns

1. **Double error handling on `LoadError`** (`conversation_view.rs`, `AcpThreadEvent::LoadError` arm).
   - That arm now calls `thread.handle_connection_lost(cx)`.
   - `handle_connection_lost` emits `ConnectionLost` whenever the thread was still observable.
   - The `ConnectionLost` handler calls `handle_load_error` with the generic "Agent connection lost…" message.
   - If a real `LoadError(error)` arrives while the thread is observable, the specific error can be followed by, and overwritten with, the generic one.
   - Worth checking the ordering. Consider skipping the `ConnectionLost` handling when the state is already `LoadError`, or having the `LoadError` arm close observation without emitting.

2. **The copy-failure path replaces the whole view state.** `copy_saved_input_button` reports a serialization failure through `handle_load_error`.
   - That moves the conversation into `LoadError` and triggers recovery snapshotting, for what is only a failed clipboard export.
   - A toast or inline error would be less disruptive.
   - `to_string_pretty` on these types is very unlikely to fail, but the handling is heavy for a clipboard action.

3. **"Discard Saved Submissions" is immediate and irreversible.**
   - It may be the only remaining copy of accepted or uncertain input.
   - A confirmation, or at least a prominent "Copy Saved Input" next to it (which is already there), would be safer.
   - The tooltip says it doesn't cancel agent work, which is good.

4. **Retained entities.** The PR description says no old model, view, transport, or task is retained. `QueuedMessageRecovery::tracked_buffers` holds `Entity<Buffer>` handles. They are probably needed so queued edits still resolve, but this is a small deviation from "data-only". Either the description or a comment should say why it's acceptable.

5. **Idempotency.**
   - `restore_recovery` calls `add_to_queue` for every queued item each time it runs.
   - Correctness depends on `this.recovery.take()` running exactly once, in the `Ok` arm, and on `restore_recovery` not being reached twice.
   - The PR description mentions tombstones for discarded input. I didn't see them in this diff, so they may be in earlier commits.
   - The test covers a second `ActivityConfirmedIdle` and repeated retries. A direct test that the queue isn't duplicated when two views restore the same recovery would be reassuring.

6. **`has_saved_input()` pins threads.** It prevents eviction and `draft_has_content` cleanup indefinitely, until the user discards. That is the intended behavior and has a test. It does mean a disconnected thread never ages out on its own.
