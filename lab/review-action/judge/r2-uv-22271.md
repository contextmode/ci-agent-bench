# REVIEW A

**Review of PR #22271: Add Pyodide installation mirrors** (the PR is already merged)

**Summary**

The PR adds three things:
- the `UV_PYODIDE_INSTALL_MIRROR` environment variable,
- the `pyodide-install-mirror` setting,
- the `--pyodide-mirror` flag on `uv python install` and `uv python upgrade`.

It follows the existing PyPy and GraalPy mirror pattern closely. It also updates the schema, the docs and the `create-python-mirror.py` script. I could only read part of the diff, because the tool output was truncated. I did not see the tests in full or the env-var and reference docs.

**What looks good**
- The change follows the existing pattern: a CLI arg, a settings field, a `PythonDownloadMirrors.pyodide` field, a masked-field warning in `uv-settings`, and a schema entry.
- `self.key.implementation().as_ref()` in `downloads.rs` is the key change. Pyodide is stored as CPython on Emscripten, and matching on the normalized implementation keeps a configured CPython mirror from applying to Pyodide downloads. The PR description explains this reasoning.
- The mirror URL has its trailing slash trimmed. Unlike the PyPy and GraalPy branches I'm comparing against, a URL that doesn't start with the GitHub prefix returns `Error::Mirror(UV_PYODIDE_INSTALL_MIRROR, url)` rather than silently falling back. That makes a mismatch visible.
- `file://` mirrors are documented and supported.
- `scripts/create-python-mirror.py` now includes the Pyodide release prefix.
- The last commit moves the mirror arguments into `uv-cli`, which fits the repo's structure.

**Potential issues and nits**
1. **Mirror selection logic is unreachable for non-Pyodide keys.** This is fine, but the new `match` on `implementation()` now covers every downloaded key. Confirm that `implementation()` returns the same value as the old `self.key.implementation` for non-Pyodide keys, such as CPython on Linux. The `.as_ref()` call suggests it returns a `Cow`, so there should be no behavior change. An existing snapshot test with a CPython mirror would cover this.
2. **Code duplication.** The Pyodide branch repeats the GraalPy and PyPy prefix-strip and format code. A small shared helper would reduce drift. This is optional, since the repo already tolerates the duplication.
3. **Slash handling.** Only trailing slashes on the mirror are trimmed. The suffix comes from a fixed prefix that ends in `/`, so the result is well-formed. A `mirror` with a query string or fragment would produce odd URLs, as with the other mirrors.
4. **Doc example.** The example `xbuildenv-0.29.5.tar.gz` appears to be the xbuildenv artifact. Check that it matches what uv actually downloads for Pyodide. If the managed download is a different artifact, the example could mislead users, though it still shows the substitution correctly.
5. **Tests.** I'd want to see integration coverage that does these three things:
   - installs Pyodide from a `file://` mirror,
   - checks that a CPython mirror setting doesn't affect Pyodide downloads (the main behavioral claim),
   - checks the `Error::Mirror` path for a URL that doesn't match the prefix.

   The repo guidelines say to prefer `insta` snapshots and integration tests under `it/`. The settings-schema snapshot in the diff was updated, but I couldn't confirm that the three cases above are covered.
6. **Security.** There is no new concern. The mirror is user-controlled configuration, like the existing mirrors. Downloads are still validated by the existing hash checks, as long as the Pyodide entries carry SHA-256 values.

**Verdict:** This is a low-risk, consistent change. The main thing I couldn't confirm is test coverage for the CPython-mirror isolation case and the mismatch error.

# REVIEW B

**Review of PR 22271: Add Pyodide installation mirrors**

This PR is already merged and approved. Overall it's a clean change that follows the PyPy and GraalPy mirror pattern closely. I read the diff only and did not build it or run the tests.

**What looks good**
- **Mirror selection:** `self.key.implementation().as_ref()` picks the mirror from the normalized implementation. Pyodide is recorded as CPython on Emscripten, so this stops it from falling into the CPython branch. It also stops a configured `UV_PYTHON_INSTALL_MIRROR` from affecting Pyodide downloads.
- **Error on unexpected URLs:** If the download URL doesn't start with the GitHub prefix, the code returns `Error::Mirror` instead of silently producing a bad URL.
- **Plumbing:** The new setting is wired through every place the other mirrors go:
  - the CLI args for install and upgrade;
  - env var parsing;
  - `combine`;
  - `OptionsWire`;
  - the `uv.toml`-only masked-field warning;
  - `PythonFindSettings` destructuring;
  - the schema, the env var docs and the mirror-creation script.
- **Tests:** The `python_list_with_mirrors` snapshots cover several cases:
  - the env var alone;
  - the env var set together with the CPython mirror;
  - the CPython mirror alone, with the default URL unchanged;
  - `uv.toml`;
  - an env var overriding `uv.toml`.
- **Style:** The tests are integration tests using `insta` snapshots, as AGENTS.md prefers.

**Issues and suggestions (minor)**
1. **Missing CLI test:** Nothing exercises `--pyodide-mirror` on `python install` or `python upgrade`. Only the help snapshot covers it. I couldn't tell whether the existing PyPy and GraalPy flags have such tests. If they do, one for Pyodide would be worth adding. If not, this matches the current state.
2. **`file://` mirrors untested:** The docs promise `file://` support. The Pyodide branch builds the URL the same way as the other branches, so it should work, but no test confirms it.
3. **Docs wording:** The setting doc says "This variable can be set…" for a config option. That wording is copied from the PyPy and GraalPy docs, so it's consistent, though "This setting" would be more accurate.
4. **Trailing slash:** A mirror with a trailing slash is handled by `trim_end_matches('/')`. The snapshots don't cover that case, and it's cheap to add.
5. **Prefix constant:** The prefix literal `https://github.com/pyodide/pyodide/releases/download/` is hard-coded inline. The same string is already used in the doc comments, the script and the filters. A named constant would reduce drift, but the other implementations also inline their prefixes.
6. **Snapshot assumption:** The tests assume `pyodide@3.13` resolves to `pyodide-3.13.2-emscripten-wasm32-musl` on every platform. If the Pyodide download entries are platform-independent, as the fixed key suggests, that's fine.

**Performance and security**
- There is no performance impact.
- The mirror URL comes from the user's own configuration. It is parsed with `DisplaySafeUrl::parse`, which redacts credentials in display output, so I see no new security concerns.

**Verdict:** Approve. The follow-ups above are optional.
