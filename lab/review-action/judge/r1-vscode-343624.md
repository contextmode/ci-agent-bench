## Review of PR #343624: Agent Host: accept managed model "fusion" as Auto

The PR is already merged. I read the diff only and did not build it or run the tests.

**Verdict:** This is a small, focused fix and I found no blocking issues.

### What it does
- It adds an exported `normalizeManagedModelId` in `copilotManagedSettings.ts`. The function trims the value, treats blank input as unset, and maps `fusion` (any case) to `auto`.
- The workbench policy path (`normalizeModelValue`) now goes through the same function.
- The Agent Host path, `getManagedModelId`, uses it in `projectCopilotManagedModelConfiguration` and `omitCopilotManagedModelDefaults`.

### Good
- **One normalizer for both paths.** The workbench and the Agent Host can't drift apart on how `fusion` is read.
- **Exact match only.** `fusion-preview` is not remapped, and a test covers that.
- **Tests cover both layers.** They check that Auto gets the managed default and the `hydrafusion` tier, and that a concrete model is not marked managed. They also cover the top-level and legacy keys, trimming and case.
- **Cleanup path.** The comment ties the alias to the runtime fix (github/copilot-agent-runtime#28619) and notes it becomes a no-op later.

### Observations and nits
1. **Layering.** `agentHost/node/copilot` now imports from `platform/policy/common`. That direction is probably fine, since the file is `common` and the agent host already depends on managed settings. Check it against the repo's layering rules.
2. **Rewritten guards.** `concreteModel` became `!!values && managedModelId === model.id && model.id !== 'auto'`. The `!!values` is only there so TypeScript narrows `values.effortLevel`. It is correct, but the intent isn't obvious, so a short comment or an early return would help. The behavior is the same as before. When `values` is undefined, `managedModelId` is also undefined and can't equal a real `model.id`.
3. **Mixed return types.** In `projectCopilotManagedModelConfiguration`, the `!schema` branch marks `model: true` for Auto. That is the intended outcome, and the test only exercises the schema branch. A one-line test for a schema-less Auto would close that gap.
4. **Naming.** The constant `COPILOT_FUSION_MODEL_ALIAS` is declared between two doc comments. It reads fine, but it could sit directly above the function that uses it.
5. **Other consumers.** I didn't check whether anything else compares `policy.values.model` directly instead of going through the normalizer. A quick grep for `values?.model` and `.values.model` in the agent host would confirm none were missed. Unmapped uses would still see `fusion`.
6. **`effortLevel` and `contextTier`.** The PR notes these don't apply to Auto. Silently ignoring them is reasonable, but a debug log when they are set alongside a managed `fusion` or `auto` could help admins who wonder why they have no effect.

### Security and performance
There are no security concerns. The change only does string normalization on admin-controlled policy values, and the cost is trivial.

## Review of PR #343624: Agent Host: accept managed model "fusion" as Auto

The PR is already merged. The change is small, focused and correct. I found no blocking issues, only a few minor points.

### What it does
- It adds `normalizeManagedModelId` in `copilotManagedSettings.ts`. The function trims the value, treats a blank value as unset, and maps `fusion` (any case) to `auto`.
- `normalizeModelValue` now calls it, so the workbench `chat.defaultModel` policy picks up the mapping.
- `copilotManagedModelConfiguration.ts` uses it through a new `getManagedModelId` helper in three places: `projectCopilotManagedModelConfiguration` (twice) and `omitCopilotManagedModelDefaults`.

### Code quality
- **Single source of truth:** one exported normalizer is shared by the workbench policy and the Agent Host. The two paths can't drift apart.
- **Exact match only:** the mapping matches `fusion` exactly, so `fusion-preview` is unaffected, and the tests cover this.
- **Good comments:** the alias constant links to the upstream runtime issue and explains that the mapping becomes a no-op once the runtime reports `auto`. Remove the shim when the runtime fix ships.
- **Dependency direction:** `platform/agentHost/node` now imports from `platform/policy/common`. That is a legal layer direction, but it adds a coupling. Check that no import-restriction rule (`.eslint` layers) objects. CI passed, so it probably doesn't.

### Potential issues and nits
1. **`!!values &&` rewrite:** the old `values?.model === model.id && ...` let TypeScript narrow `values` to defined. The new `!!values && managedModelId === ...` keeps that narrowing, so the code is correct. It also adds a subtle behavior: if `values` is undefined, `managedModelId` is undefined, so the comparison is false anyway. The `!!values` guard is only there for narrowing. A short comment, or computing `const values = policy.values` first, would make that clearer.
2. **Repeated normalization:** `getManagedModelId` runs once per model projection, and the string work is trivial. This is not a performance concern.
3. **Edge case:** if a real catalog model ever had the id `fusion`, it could no longer be selected through managed settings. That is unlikely, and the PR description explains the reasoning.
4. **Behavior change for whitespace:** `projectCopilotManagedModelConfiguration` now trims `values.model` before comparing, where it compared exactly before. This is arguably a fix, because it matches the workbench policy path. Neither the description nor the tests mention it. A test with a padded concrete model id, such as `' gpt-5 '`, would pin it down.

### Test coverage
- The agent-host test checks that Auto is marked as the managed default, that `tier` becomes `hydrafusion`, and that a concrete model is not marked. It uses mixed-case `Fusion`.
- The policy test covers the top-level key, the legacy key, the trimmed and mixed-case input, and the `fusion-preview` pass-through.
- **Missing:** `omitCopilotManagedModelDefaults` has no direct test with a `fusion` value. Auto never counts as a concrete model, so the behavior is unchanged there, but a test would guard the new code path.
- **Missing:** no test covers a blank or whitespace-only `model` after the refactor. The previous test may still cover it.

### Security and performance
- **Security:** no concerns. The change maps one string constant and does no parsing or I/O.
- **Performance:** no concerns.
